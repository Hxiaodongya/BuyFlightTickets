# 城市级航班价格追踪配置设计

## 目标

把扩展的查询配置改为城市级选择：用户只选择出发城市、到达城市和一个或多个目标出行日期，不输入机场名称或三字码。使用 Vue 3、Vite 和 Element Plus 构建扩展页面，同时保留国航/南航采集、每日调度、手动补采和本地价格历史。

## 用户界面

- 查询计划表单使用 Element Plus 控件。出发地和到达地为可搜索的中国航线城市选择器，只展示城市名；选择项不暴露机场名称、机场三字码或航司内部代码。
- 日期控件支持一次选择多个目标出行日期；保留每日采集时间、采集航司和启停状态。
- 删除计划名称、乘客数和舱位控件。采集参数固定为一位成人和经济舱，由采集适配器内部保证。
- 直达/中转和航司/航班筛选仍在有采集数据后使用，只对本地记录实时过滤和重绘，不触发重新采集。
- 弹窗继续提供今日状态、手动采集和历史页入口；完整配置和价格历史在扩展页中操作。
- 价格口径继续显示为“列表价（未含税费）”。

## 城市与航司适配

- 查询计划保存稳定的城市标识和城市显示名，不保存用户填写的机场代码。城市选项由本地维护的国内航线城市表提供，并可搜索。
- 每个航司适配器把城市标识转换为其公开查询流程所需的位置值。若航司查询流程确需机场级请求，机场映射和多机场汇总只存在于适配器内部，界面始终保持城市级选择。
- 对某个已选城市无法可靠映射的航司，记录该航司任务失败并给出明确原因；不以机场猜测、不保存虚构价格，也不影响其他航司任务。
- 采集请求固定为一位成人、经济舱；过滤仍采集所有可见直达及中转结果。

## 数据迁移与兼容

- 新计划字段以 `originCityId`、`originCityName`、`destinationCityId`、`destinationCityName`、`travelDates`、`airlineCodes`、`collectionTime` 和 `enabled` 为核心。
- 升级时把旧计划中已知机场代码映射到城市；无法映射的计划保留原记录并标记不可运行，等待用户在新表单中修正，不能静默删除。
- 既有采集观察和价格历史继续保留。路线展示优先从关联计划显示城市名；旧观察不得因为迁移而丢失价格或采集时间。
- 种子示例改为杭州至长春、2027-02-04 和 2027-02-05，航司仍为国航和南航，固定经济舱与一位成人。

## 页面与构建架构

- 使用 Vue 3 单页组件组织弹窗和历史/设置页面，以 Element Plus 实现表单、选择器、日期、按钮、筛选和状态反馈。
- Vite 构建两个扩展页面；Manifest V3 后台 Service Worker 和航司 content scripts 保持静态扩展脚本，在构建目录中按 manifest 路径复制，不从远程加载代码。
- 价格历史图表继续使用现有本地 SVG 图表模型；筛选和存储消息行为保持原语义。
- Chrome 加载路径改为构建产物目录；单元测试覆盖新计划契约、旧数据迁移、城市到航司查询值的转换和现有采集/图表行为。

## 范围与限制

- 本次仅实现中国国内城市和国航、南航；其他航司后续按适配器扩展。
- 不增加机场选择、自由输入城市、登录自动化、订单操作、云端服务或验证码绕过。
- 外部航司页面变化或阻止自动查询时按现有失败策略处理，不伪造结果。
- 用户手动加载 Chrome 扩展验证真实航司页面；本地自动化不启动 Playwright。

## 验收标准

- 出发地和到达地只能从可搜索的国内城市选项中选择，页面不显示机场名或机场三字码输入项。
- 用户可选择多个出行日期，并保存/编辑/启用/停用/删除计划。
- 计划表单不出现计划名称、乘客数和舱位字段；采集请求始终为一位成人、经济舱。
- 同城出发/到达被阻止；缺城市、缺日期或缺航司时不能保存。
- 迁移可把已知旧机场代码转换为城市；未知旧计划仍保留且不可误采。
- 航司适配只在内部处理必要的位置参数；不能映射的航司任务报告失败，不丢失其他来源结果。
- 日期、行程类型和航司/航班筛选只过滤本地历史并实时更新图表。
- `npm test`、`npm run build` 和 `npm run verify` 均通过；构建产物包含 manifest、后台脚本、内容脚本、两个页面及其本地依赖资源。
