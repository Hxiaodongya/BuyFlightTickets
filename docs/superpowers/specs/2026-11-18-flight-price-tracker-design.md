# 航班价格追踪插件设计

## 目标

构建一个 Chrome Manifest V3 扩展，按日查询用户关注的航线与出行日期，保存国航和南航航班的票价观察记录，并用折线图呈现价格变化。用户可以手动立即采集，以便在 Chrome 关闭或电脑睡眠导致计划任务错过后补采。

## 方案选择

- 推荐方案：扩展本地定时，通过 Chrome 定时事件调度；在非活动标签页打开航司公开查询页面，由对应内容脚本提取搜索结果。数据留存在本地，无服务器依赖，适合“Chrome 打开时运行”的要求。
- 云端调度方案：后端定时查询可在 Chrome 关闭时运行，但需要部署服务、维护凭据和承担持续运行成本，不符合当前范围。
- 手动记录方案：不依赖网站自动化，但不能满足每日自动查询的核心需求。

首版采用推荐方案。每个航司有独立适配器，便于以后新增航司。自动化只读取公开查询结果，不登录账户、不提交订单、不绕过验证码或访问控制。

## 用户流程

1. 用户打开扩展，配置一个或多个查询计划。必填项为计划名称（可自动生成）、出发机场、到达机场、一个或多个出行日期和至少一个采集航司。机场选择同时显示城市名和机场三字码，避免同城多机场歧义。
2. 计划可设置成人乘客人数（默认 1 人）、舱位（默认经济舱）和每日采集时间（默认本地时间 09:00）。首版仅支持单程、成人乘客；儿童/婴儿、往返行程暂不纳入。
3. 首次启动预填示例：杭州萧山 HGH 至长春龙嘉 CGQ，出行日期为 2027-02-04 和 2027-02-05，采集航司为国航和南航；用户可编辑或删除。
4. 每日计划时间到达时，扩展依次打开启用航司的非活动查询标签页，读取该路线和日期的直达及中转结果，并在采集完成后关闭其创建的标签页。采集阶段不应用图表筛选条件，以便筛选结果完整。
5. 扩展弹窗显示今日状态、最近采集时间、成功/失败数量，并提供“立即采集”和打开价格历史的入口。
6. “立即采集”对所有启用中的查询计划执行同一流程。自动任务和手动任务共用队列；运行期间禁止重复启动，并持续显示进度。
7. Chrome 恢复运行后，扩展显示“今日尚未采集”或“采集不完整”状态，用户可以手动补采。图表只记录实际采集时间，不回填没有采集到的日期。

## 图表与价格口径

- 横轴为本地日期下的实际采集日期；纵轴为人民币票价。
- 每条折线按查询路线、出行日期、承运航司、航班号及可获取的舱位/票价产品区分。国航与南航使用稳定且可区分的颜色。
- 每个采集日最多为每个航班系列记录一个最新观察值。若当天没有该航班或解析失败，图表显示间断，不将缺失值绘制为零，也不跨日伪造数据。
- 历史图表提供查询路线和出行日期选择、行程类型筛选（不限/直达/中转）和航司/航班筛选模式。航司模式选择航司，航班模式选择航班号；选项由已采集的数据生成。
- 图表筛选只在本地对已保存记录做交集过滤并立即重绘，不重新访问航司网站。无匹配数据时显示空结果状态。
- 只在来源页面能明确识别时记录含税总价、舱位和票价产品；不能确认的字段标为未知，不声称不同票价条件可直接比较。
- 每条观察包含采集时间、出发/到达机场、出行日期、航司、航班号、经停次数、价格、币种、乘客人数、舱位/票价信息（可得时）、来源和采集任务类型（计划或手动）。

## 架构与数据

- 扩展使用 Manifest V3；后台 Service Worker 负责定时任务、任务队列、运行互斥和状态恢复。
- 航司适配器负责打开各自官方查询页面并解析结果，初始实现国航和中国南方航空。适配器不得依赖其他航司的 DOM 结构。
- 扩展页面负责查询计划编辑、状态、手动采集入口和历史图表。Chrome 本地存储保存配置、采集批次和价格观察；首版不上传数据、不要求账号。
- 查询计划保存计划名称、机场代码、出行日期、成人乘客人数、舱位、采集航司和本地每日采集时间。每批任务和每个航司查询分别保存状态。允许部分成功；失败原因按航司和查询计划呈现，并保留上次成功数据。
- 查询页面超时、登录要求、验证码、空结果、页面结构变化或价格解析不明确时，记录明确失败状态，不生成价格点。任务结束时清理扩展创建的查询标签页。

## 首版范围与限制

- 支持多个查询计划，每个计划支持多个出行日期。
- 支持航司仅为中国国际航空和中国南方航空。
- 每日采集时间可配置，默认本地时间 09:00。
- Chrome 关闭时扩展不能执行；电脑睡眠可能延迟任务。手动采集需要 Chrome 恢复运行后由用户触发。
- 不包含价格预测、购买/下单、账户登录、云同步、通知推送、其他航司和跨设备同步。
- 航司页面是外部依赖；首版需对真实公开查询流程进行验证。若站点要求人工验证或阻止自动化，明确报告该来源无法自动采集，不尝试规避。

## 验收标准

- 用户可新增、编辑、启用、停用和删除查询计划，并能设置机场、多个出行日期、成人乘客人数、舱位、采集航司及每日采集时间；缺少必填项时不能保存。
- 手动采集能执行当前启用的计划；重复触发会被阻止，界面能显示运行中、成功、部分成功和失败状态。
- 今日无数据或仅部分来源成功时，弹窗会明确提示；用户可以立即补采。
- 至少一条采集记录能在图表上按实际采集日期正确呈现；不同航班/出行日期的系列不会混淆，缺失日显示为间断。
- 采集后切换出行日期、直达/中转和航司/航班筛选时，图表能基于本地数据立即更新，且不会触发新的采集。
- 失败和无法解析的价格不会被保存成有效票价。
- 核心状态、日期/价格归一化、图表分组及航司解析逻辑具备自动化单元测试；扩展通过构建并可在 Chrome“加载已解压的扩展程序”中安装。
- 真实航司页面验证应记录各航司的可采集字段与限制；无法可靠访问的航司标记为不可用，不以模拟数据冒充真实采集结果。
